## 1. 前端模块总览

前端按「端」划分视图，按「业务」划分 API，公共能力沉淀在 components/composables/utils。

| 模块 | 路径 | 职责 |
|------|------|------|
| API 接口层 | `src/api/` | 与后端 REST 一一对应的函数封装，返回类型定义 |
| 通用组件 | `src/components/` | CURD 三件套、上传、富文本、图表、字典、表格选择等 22 个组件 |
| 布局 | `src/layouts/` | 5 套布局（Base/Left/Top/Mix/Blank）+ 商家布局 MerchantLayout |
| 路由 | `src/router/` | 路由表 + 导航守卫（登录校验/角色过滤/动态菜单） |
| 状态管理 | `src/store/` | Pinia：user（登录态）、permission（菜单权限）、tags-view、app、dict、settings、tenant |
| 工具层 | `src/utils/` | request（Axios 封装）、auth（token）、storage、download/export、format、validate |
| 页面 | `src/views/` | shop（前台）/ merchant（商家）/ eshop+system（后台）/ 其他 |

### 1.1 API 层设计约定

- 全部经由 `src/utils/request.ts`（Axios 实例）发起，拦截器统一：注入 `Bearer token`、`showLoading`、`code===200` 时解包返回 `data`、401 跳登录。
- `api/eshop/*.ts` 为电商业务接口，`api/system/*.ts` 为 RBAC 系统管理接口。
- **类型定义方式（当前现状）**：接口返回类型在 `api/eshop/*.ts` 文件内联定义（如 `ProductItem`、`OrderVO`），与后端 `vo/` 手工对齐，未做自动同步。

### 1.2 关键组件说明

| 组件 | 用途 | 备注 |
|------|------|------|
| `components/CURD/` | PageSearch + PageContent + PageModal + usePage | 后台列表页「搜索+表格+弹窗」通用骨架，后台大量复用 |
| `components/ECharts/` | ECharts 封装 | 仪表盘/统计页复用 |
| `components/Upload/` | Single/MultiImageUpload、FileUpload | 图片/文件上传 |
| `components/TableSelect/` | 表格选择器 | 选商品/选用户场景 |
| `components/DictSelect/DictTag` | 字典渲染 | 对接系统字典 |

### 1.3 路由组织

```
src/router/index.ts
├── constantRoutes      # 无需权限（login/register/error…）
├── asyncRoutes         # 需登录 + 角色校验的页面路由（按端分组）
│   ├── shop/*          #   商城前台（home/product/cart/checkout/order/coupon/seckill/signin…）
│   ├── merchant/*      #   商家中心（MerchantLayout 包裹）
│   ├── eshop/*、system/*  # 管理后台
└── guards/permission.ts  # 全局前置守卫：登录校验 → 拉取用户信息 → 动态生成菜单
```

## 2. 后端模块总览

后端为经典三层架构（Controller → Service → Mapper），按业务域划分模块。实体（entity）、DTO（请求）、VO（响应）三类对象区分清晰。

```
controller/  （30 个，仅做参数接收/鉴权/结果返回，业务在 Service）
service/     （接口 + impl，承载全部业务逻辑，事务边界在此）
mapper/      （MyBatis-Plus BaseMapper + 少量自定义 SQL 的 XML）
repository/  （ES 搜索的 Spring Data Repository）
entity/      （34 张表实体，Lombok @Data + MyBatis-Plus 注解）
dto/         （44 个请求对象，配合 jakarta validation）
vo/          （18 个响应对象，组合多表数据）
```

### 2.1 业务域 → 核心类对照

| 业务域 | Controller | Service（impl） | 关键实体 |
|--------|-----------|----------------|----------|
| 用户 | UserController、EmailAuthController、CaptchaController | UserServiceImpl、EmailServiceImpl | User |
| 商品 | ProductController、ProductSearchController、CategoryController | ProductServiceImpl、ProductSyncServiceImpl、CategoryServiceImpl | Product、Category、ProductSku、ProductSpec、ProductImage、ProductSizeChart |
| 购物车 | CartController | CartServiceImpl | Cart |
| 订单 | OrderController、MerchantController(发货) | OrderServiceImpl、OrderShipmentServiceImpl | Order、OrderItem、OrderShipment、PaymentRecord |
| 营销 | CouponController、AdminCouponController、UserCouponController、SeckillController、AdminSeckillController、ActivityController | CouponServiceImpl、UserCouponServiceImpl、SeckillServiceImpl、ActivityServiceImpl | Coupon、UserCoupon、SeckillSession、FestivalCouponPlan、UserSigninRecord |
| 收藏/评论/足迹 | FavoriteController、ProductCommentController、BrowseHistoryController | 对应 ServiceImpl | Favorite、ProductComment、VisitLog |
| 退款 | RefundController、AdminRefundController、OrderController(退款) | OrderServiceImpl（内嵌） | RefundApplication、RefundProgressLog、RefundSatisfaction |
| 商家 | MerchantController、MerchantApplyController、AdminMerchantApplyController、MerchantMessageController、StoreController | MerchantApplyServiceImpl、MerchantMessageServiceImpl | MerchantApply、MerchantMessage、StoreDesign |
| 通知 | NoticeController、SseController | NoticeServiceImpl、OnlineUserServiceImpl | Notice、NoticeRead |
| 统计 | AdminDashboardController、StatisticsController | StatisticsServiceImpl | Order、VisitLog、User |
| 日志/审计 | OperationLogController | OperationLogServiceImpl | OperationLog（LogAspect 自动写入） |

## 3. 核心业务模块详解

### 3.1 用户与认证模块

**前端**：`views/login/`（登录/注册/找回密码）、`api/auth.ts`、`api/eshop/user.ts`、`store/modules/user.ts`
**后端**：

| 类 | 职责 |
|----|------|
| `UserController` | 注册、登录、用户信息、管理员分页/冻结/解冻/搜索/在线踢下线、改密、邮箱绑定/解绑/重置密码、注销 |
| `JwtUtil` | JWT 生成/解析（含过期校验） |
| `TokenUtils` | 从 Authorization 头提取 token |
| `JwtAuthenticationFilter` | 每请求解析 token → 写入 SecurityContext；失败时手写 401 响应 |
| `SecurityConfig` | 过滤链：公开路径白名单 + `anyRequest().authenticated()` |

**登录流程**：`POST /api/user/login`（账号密码 + 图形验证码）→ 校验 → 签发 JWT → 返回用户信息；前端存 localStorage → 后续请求带 `Authorization: Bearer xxx`。

### 3.2 商品模块（含 SKU/ES 搜索）

**前端**：`views/shop/product/detail.vue`（详情+SKU选择）、`views/shop/home/index.vue`、`views/merchant/Products.vue + ProductForm.vue`（商家发布/编辑，含规格/SKU/尺寸表维护）、`views/eshop/product/index.vue`
**后端**：

| 类 | 职责 |
|----|------|
| `ProductController` | 商品 CRUD、分页、上下架、图片、热门、拼音 |
| `ProductSearchController` | ES 搜索 `/api/product/es/search`（高亮） |
| `ProductServiceImpl` | 商品增删改查、SKU 库存汇总同步、定时同步热门 |
| `ProductSyncServiceImpl` | MySQL → ES 索引同步（增删改全量） |
| `ProductDocument` + `ProductSearchRepository` | ES 文档映射与操作 |

**SKU 一致性策略**：`product.stock/sales = SUM(sku.stock/sales)`，在 下单/支付/退款/定时任务 四路径同步，Redis 缓存写后失效。

### 3.3 购物车模块

**前端**：`views/shop/cart/index.vue`、`api/eshop/cart.ts`
**后端**：`CartController` + `CartServiceImpl`

支持 SKU 粒度（`cart` 表含 `sku_id`/`sku_specs`），同商品不同 SKU 可共存（唯一键 `user_id+product_id+sku_id`）。

### 3.4 订单模块（核心）

**前端**：`views/shop/checkout/index.vue`（结算）、`views/shop/order/list.vue` + `detail.vue`、`views/merchant/Orders.vue`（发货）
**后端**：`OrderController` + `OrderServiceImpl`（约 1022 行，最复杂模块）

| 流程 | 方法 | 说明 |
|------|------|------|
| 创建订单 | `createOrder` | 校验商品/库存 → 按商家拆发货单 → 生成订单明细（快照）→ 扣库存 → 核销优惠券 → 通知商家 |
| 支付 | `payOrder` | 模拟支付 → 更新状态 → 增加销量 → 清缓存 |
| 取消 | `cancelOrder` | 用户取消 + 定时自动取消（5 分钟扫超时订单） |
| 发货 | `MerchantController.ship` | 商家按发货单发货（快递公司/单号） |
| 确认收货 | `confirmReceive` | 用户确认/定时自动确认 |
| 退款 | `applyRefund` → `auditRefund` | 商户初审 → 管理员终审 → 执行退款 → 回退库存销量 → 满意度评价 |

**订单状态机**：`0 待付款 → 1 待发货 → 2 待收货 → 3 已完成`；`0 → 4 已取消`；`1/2/3 → 5 退款中 → 6 已退款`。

### 3.5 营销模块（优惠券/秒杀/签到）

**前端**：`views/shop/coupon/`（CouponCenter、MyCoupon）、`views/shop/seckill/index.vue`、`views/shop/activity/SignIn.vue`、`views/eshop/coupon|seckill/index.vue`
**后端**：

| 类 | 职责 |
|----|------|
| `CouponServiceImpl` | 优惠券模板 CRUD（满减/折扣） |
| `UserCouponServiceImpl` | 领券（校验库存/限领）、可用/已用查询、连续签到计算 |
| `SeckillServiceImpl` | 秒杀场次 CRUD、Redis 预减库存、场次状态机、定时预热/撤销 |
| `ActivityServiceImpl` | 签到、签到里程碑、节日优惠券活动（festival_coupon_plan 联动） |

**秒杀流程**：`GET /api/seckill/sessions` 列表 → `POST /api/seckill/{id}`：Redis `decrement` 限流 → DB 扣库存 → 发放优惠券。

**节日券+签到联动**：签到达到 `festival_coupon_plan.required_signin_days` → 可领取对应优惠券（创新点）。

### 3.6 退款模块

**前端**：`views/shop/order/list.vue`（申请/进度/满意度弹窗）、`views/eshop/refund/index.vue`、`views/merchant/Refund.vue`
**后端**：`RefundController`、`AdminRefundController` + `OrderServiceImpl`（auditRefund）

**两级审核状态机**：`0 待商户审核 → 1 待管理员审核 → 2 已通过 → 4 执行中 → 5 已退款`；任一环节拒绝 → `3 已拒绝`。进度写入 `refund_progress_log`，退款完成收集 `refund_satisfaction`。

### 3.7 通知与实时推送

**前端**：`components/NoticeDropdown/`、`views/profile/notice/index.vue`、`composables/sse/`
**后端**：`NoticeController`（CRUD/发布/撤回）、`SseController`（SSE 长连接：在线人数/字典同步）、`NoticeServiceImpl`

`sys_notice` 表以 `biz_type`（new_order/order_paid/refund_success…）+ `biz_id` 支撑订单、退款、留言等多场景通知。

### 3.8 统计看板模块

**前端**：`views/dashboard/index.vue`、`views/merchant/Statistics.vue`、`api/eshop/dashboard.ts`
**后端**：`AdminDashboardController` + `StatisticsServiceImpl`

提供：销售趋势、用户增长、热销商品 TopN、转化率（漏斗）、访客量/访问趋势（VisitLog）。

## 5. 典型调用链

### 5.1 用户下单全链路

```
前端 checkout/index.vue
  → api/eshop/order.ts createOrder(dto)
  → POST /api/order/create
  → OrderController.createOrder（token→userId）
  → OrderServiceImpl.createOrder（@Transactional）
      ├─ 校验商品/库存（check-then-act）⚠️
      ├─ 优惠券抵扣（未校验归属）⚠️
      ├─ 创建 order + order_shipment（按商家）+ order_item（快照）
      ├─ 扣库存 + SKU 汇总同步 product.stock
      ├─ 核销 user_coupon
      └─ noticeService.createAndPublish("new_order") 通知商家
  → 返回 order → 前端跳支付
  → PUT /api/order/pay/{id} → payOrder：更新状态/增销量/清 Redis 缓存
```

### 5.2 秒杀全链路

```
前端 seckill/index.vue（1s 倒计时 + 10s 刷新列表）
  → POST /api/seckill/{sessionId}
  → SeckillController.seckill
      ├─ 校验场次状态/时间/限购
      ├─ Redis DECR seckill_stock 预减（并发闸门）
      ├─ DB selectById + updateById 扣库存 ⚠️
      └─ 发放优惠券 → user_coupon
  → 前端提示抢购结果
```

### 5.3 退款全链路

```
前端 order/list.vue 申请退款
  → POST /api/order/refund/apply → applyRefund
  → refund_application(status=0) + refund_progress_log
  → 商户：PUT /api/order/merchant/refund/audit（status 0→1 或 3）
  → 管理员：PUT /api/order/admin/refund/audit（status 1→2 或 3）
  → 执行退款：status 4→5，回退 sku 库存/销量、payment_record.status=2、order.status=6
  → POST /api/order/refund/satisfaction 满意度评价
```

### 5.4 ES 搜索全链路

```
商家/管理员改商品 → ProductServiceImpl 写 MySQL
  → ProductSyncServiceImpl.syncAllProducts / syncOneProduct 同步 ES product_index
用户搜索 → GET /api/product/es/search?keyword=
  → ProductSearchController → ProductSearchRepository（高亮）
  → 兜底：ES 不可用时回退 ProductController 关键字 LIKE 查询
```
