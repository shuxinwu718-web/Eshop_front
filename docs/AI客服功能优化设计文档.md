# AI 客服功能优化设计文档

> 版本：v1.0 · 2026-08-03 · 状态：✅ 已实现（基础能力均已上线；Agent 工具能力见《AI客服Agent化设计文档》v1.2）
> 前端：`Eshop`（Vue3 + Element Plus） · AI 服务：`E:\Python-wordkspace\ai-customer-service`（FastAPI + 通义千问 qwen-turbo）

---

## 1. 背景与现状

AI 客服功能第一版已上线可用：

| 项 | 现状 |
|----|------|
| 入口 | 仅"我的订单"页（`/shop/order`）header 右上角一个"联系客服"小按钮 |
| 交互 | `el-dialog` 弹窗（520px 固定宽度）内嵌聊天 |
| AI 服务 | `POST /ai/chat`，`{message}` → `{reply, success, error}`，已接通通义千问 |
| 频率限制 | 前端已实现（60 秒内最多 6 条） |

## 2. 问题分析

| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| 1 | 客服入口不显眼 | 按钮只存在于订单页，且样式普通 | 用户找不到客服，售后/咨询触达率低 |
| 2 | 弹窗不适配移动端 | `el-dialog` 固定 520px 宽，小屏溢出、输入不便 | 移动端体验差 |
| 3 | AI 回答与系统无关 | [main.py](file:///E:/Python-wordkspace/ai-customer-service/main.py) 的 `call_ai` 用 `prompt=message` 直接调用通义千问，**无 system prompt**；且无会话上下文 | AI 不知道这是电商系统，回复英文通用话术，无法解答退款/秒杀/签到等系统问题 |
| 4 | 无多轮上下文 | 每次请求独立，AI 记不住上一轮 | 追问"那退到哪里？"时 AI 无从理解 |

## 3. 优化目标

1. **全局醒目入口**：悬浮客服按钮，任何页面可见，点击进入独立客服页面
2. **页面化 + 移动端适配**：独立路由页面，桌面/移动端自适应
3. **AI 回答贴合系统**：注入 system prompt + 内置 FAQ 知识库，中文回答系统相关常见问题
4. **多轮对话**：携带会话上下文，支持追问
5. **保留并强化频率限制**（前端限流 + 后端兜底限流）

## 4. 方案设计

### 4.1 前端改造

#### 4.1.1 全局悬浮客服按钮（FAB）

- 组件：`src/components/CustomerServiceFab/index.vue`，挂载在全局布局（所有 shop 布局页面可见）
- 位置：页面右下角固定悬浮球（圆形，客服图标 + 红点提示）
- 行为：
  - 桌面：悬浮球下方展开"气泡卡片"（快捷问题 + 最近消息），点击"进入客服中心"跳转客服页
  - 移动端：点击悬浮球直接跳转客服页
- 客服页自身不显示悬浮球（避免重叠）

#### 4.1.2 独立客服页面

- 路由：`shop/customer-service`（`name: "CustomerService"`，`roles: ["USER", "MERCHANT"]`，菜单隐藏）
- 组件：`src/views/shop/customerService/index.vue`
- 布局（复用/改造现有 `AiCustomerService.vue` 的聊天 UI）：
  - 头部：返回按钮 + "AI 智能客服" + 清空会话
  - 消息区：气泡列表，自动滚动，正在思考动画
  - 快捷区：常见问题标签（点击即问）
  - 输入区：文本框 + 发送（回车发送）
- 自适应：
  - 移动端（< 768px）：全屏，输入框固定底部
  - 桌面端：内容区居中（`max-width: 760px`）
- 订单页原有"联系客服"按钮改为跳转客服页（保留，入口增强）

#### 4.1.3 消息与上下文

- 会话消息保存在组件内存（`sessionStorage` 可选持久化，刷新不丢）
- 发送时把最近 10 条消息作为 `history` 传给 AI 服务

#### 4.1.4 频率限制（前端）

- 保留现有策略：60 秒内最多 6 条，超限提示剩余等待秒数
- 发送按钮置灰倒计时（体验优化，可选）

### 4.2 AI 服务改造（Python）

#### 4.2.1 系统提示词（System Prompt）

新增 `system_prompt.py`，内容要点：

- 身份：你是"E-Shop 电商系统"的 AI 客服助手
- 职责：解答用户关于系统使用的问题（注册登录、下单支付、订单、退款、秒杀、签到、优惠券、商家入驻等）
- 风格：始终用简体中文、简洁专业、礼貌；不知道的如实说明并建议联系人工客服
- 约束：不回答与系统无关的问题（如编程、数学等），引导回系统话题

#### 4.2.2 FAQ 知识库（内置）

`faq.py` 维护常见问题 → 标准答案，注入 system prompt。覆盖（基于系统实际功能）：

| 分类 | 常见问题 |
|------|---------|
| 账号 | 如何注册/登录？如何找回密码？（邮箱验证码登录） |
| 下单 | 如何下单？下单后如何支付？（模拟支付） |
| 订单 | 订单状态有哪些？（待付款/已付款/已发货/已完成/已取消/退款中/已退款） |
| 退款 | 如何申请退款？退款流程？多久到账？ |
| 秒杀 | 如何参加秒杀？秒杀下单规则？ |
| 签到/优惠券 | 如何签到？签到奖励？如何领取优惠券？优惠券使用规则？ |
| 商家 | 如何申请成为商家？如何管理店铺？ |
| 其他 | 如何联系人工客服？ |

#### 4.2.3 多轮对话

- `call_ai` 改用 `messages` 数组方式调用通义千问（DashScope `Generation.call` 支持 `messages` 参数）
- 消息结构：`[system, ...history(用户与助手历史), user(当前问题)]`

#### 4.2.4 后端限流（兜底）

- 简单 IP 限流：`每分钟最多 10 条`，超限返回 429 + 提示（基于内存字典，无需 Redis）

### 4.3 接口规范（向后兼容扩展）

```
POST http://localhost:5000/ai/chat
```

请求体：

```json
{
  "message": "如何申请退款？",
  "history": [
    { "role": "user", "content": "我买的东西不喜欢" },
    { "role": "assistant", "content": "可以在订单中申请退款……" }
  ]
}
```

响应体（不变）：

```json
{ "reply": "…", "success": true, "error": null }
```

> `history` 可选，不传则兼容旧调用。
