# 商品介绍（富文本）功能实施计划

> 目标：在商品详情界面实现商品介绍展示功能，商家通过富文本编辑器（所见即所得）创建/编辑/发布富媒体商品介绍，支持版本控制与内容审核。
> 状态：方案已确认（复用现有 WangEditor 富文本编辑器；审核期间展示最近通过版本），待实施。

## 一、需求要点

1. 商品介绍内容支持富媒体格式：图片、音频、图文混排等（HTML 富文本承载）
2. 集成所见即所得富文本编辑器，商家直观编辑与预览
3. 前端富文本渲染，商品详情页正确展示全部富媒体内容
4. 现有编辑器组件复用评估与集成方案（见第四节，结论：**复用**现有 WangEditor 组件并增强）
5. 富媒体内容存储、加载、显示性能满足生产要求
6. 内容版本控制：商家查看与恢复历史版本
7. 内容审核机制：发布内容符合平台规范

## 二、数据库变更

| 变更 | 说明 |
| --- | --- |
| `ALTER TABLE product MODIFY description LONGTEXT` | 描述列由 `varchar(500)` 扩容，存富文本 HTML |
| 新建表 `product_intro_version` | 版本 + 审核状态 |

`product_intro_version` 表结构：

```sql
CREATE TABLE IF NOT EXISTS `product_intro_version` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `product_id` bigint NOT NULL COMMENT '商品ID',
  `version_no` int NOT NULL COMMENT '版本号（每次提交审核递增）',
  `content` longtext NOT NULL COMMENT '富文本 HTML 正文',
  `status` tinyint NOT NULL DEFAULT 0 COMMENT '0-草稿 1-待审核 2-已通过 3-已驳回',
  `audit_remark` varchar(500) DEFAULT NULL COMMENT '驳回原因/审核意见',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_product_status` (`product_id`, `status`),
  KEY `idx_product_version` (`product_id`, `version_no`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品介绍版本';
```

增量脚本：`sql/V20260811__product_intro_version.sql`

## 三、后端接口

### 1. 商家端 `MerchantIntroController`（`/merchant/intro`，沿用商家鉴权）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/product/{productId}` | 获取编辑内容（草稿优先，无草稿取最近通过版本） |
| POST | `/draft` | 保存草稿（覆盖当前草稿，不生成新版本号） |
| POST | `/submit` | 提交审核 → 生成新版本 `version_no + 1`，status=1 |
| GET | `/versions/{productId}` | 版本列表（仅元数据：版本号/状态/时间/驳回原因） |
| GET | `/versions/{id}` | 版本正文 |
| POST | `/restore/{id}` | 恢复历史版本 → 内容回填为当前草稿 |

### 2. 管理端 `AdminIntroAuditController`（`/admin/intro-audit`，`@PreAuthorize("hasRole('ADMIN')")`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/pending` | 待审核分页（关联商品名、商家名） |
| POST | `/audit/{id}` | 通过（status=2，同步更新 `product.description`）/ 驳回（status=3 + `audit_remark`） |

### 3. 商品详情

- `description` 随商品主查询返回（内容 = 最近一次审核通过版本），前端富文本渲染

## 四、现有编辑器组件复用评估（需求点 4）

现有 `src/components/Editor/index.vue` 基于 **`@wangeditor-next/editor`**（WangEditor-next，Vue3 官方适配），通知管理在用，**结论：复用并增强**。

- **4a 功能完整性**：Toolbar + Editor 所见即所得，`v-model` 绑定 HTML，通知模块已验证；缺口为：①未配置图片/音视频上传（当前图片走 base64，大图膨胀）；②`placeholder` 写死；③无只读预览形态。
- **4b 复用评估**：①图片上传通过 `MENU_CONF['uploadImage']` 对接已有 `/api/v1/files` 即可（约 20 行）；②`placeholder` 改为可配置 prop（1 行）；③详情页/审核页预览直接用 `v-html` 渲染（无需编辑器只读模式），商家自发布内容，风险可控。**改动量远小于重写，无新增依赖。**
- **4c 结论**：复用现有 Editor 组件，增强上传与占位符配置。
- **4d**：不适用（已复用）。若未来需要 Markdown 源码模式可再评估 `md-editor-v3`。

## 五、前端实现

1. **增强组件** `src/components/Editor/index.vue`：
   - 新增 prop：`placeholder`（默认"请输入内容..."）、`upload`（是否启用上传，默认 true）
   - 配置 `MENU_CONF['uploadImage']`：调 `/api/v1/files` 上传，返回 URL 自动插入
   - 音视频上传可选：`MENU_CONF['uploadVideo']`（联动 `/api/v1/files`）
   - 保持 `v-model` 契约不变，**通知管理现有调用零改动**
2. **商家端** `src/views/merchant/ProductForm.vue`：
   - 「商品描述」textarea 替换为 `Editor` 组件
   - 新增「保存草稿 / 提交审核 / 版本历史」按钮
   - 版本历史弹窗：版本列表（含状态/驳回原因）+ `v-html` 预览 + 一键恢复
3. **详情页** `src/views/shop/product/detail.vue`：
   - `<p>{{ description }}</p>` 替换为富文本容器（`v-html` + 基础样式容器，图片懒加载 / 音频原生播放）
4. **管理端** 新页面 `src/views/eshop/introAudit/index.vue` + 路由注册：
   - 待审核列表（商品名 / 商家 / 版本号 / 提交时间）
   - `v-html` 正文预览 + 通过 / 驳回（驳回必填原因）

## 六、审核流与展示策略（已确认）

```
商家编辑草稿 ──提交审核──▶ 生成新版本(status=1)
                              │
                    ┌─────────┴─────────┐
                 管理端通过(status=2)   管理端驳回(status=3)
                    │ 同步 product.description │
                    ▼                    └─▶ 商家查看驳回原因，修改后重新提交
             详情页展示最新通过版本
```

- 审核期间详情页继续展示**最近通过版本**（`product.description` 不受影响，新版本通过后才覆盖）
- 商家可随时查看 / 恢复任意历史通过版本

## 七、性能与安全

- 版本列表接口只返回元数据，正文按需加载（`GET /versions/{id}`）
- 详情页富文本容器图片 `loading="lazy"`，音频原生 `<audio>`，避免长文阻塞首屏
- 富媒体文件（图片/音频）统一走 `/api/v1/files` 文件服务，DB 仅存 HTML 与 URL，不存 base64
- XSS：内容由登录商家自产、经管理员审核后发布，`v-html` 渲染风险可控；如需更严格可在渲染端引入 DOMPurify（暂不引入，保持依赖精简）
