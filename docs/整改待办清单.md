## A 组：高危必做（答辩必问 / 影响演示观感）

### A1. S7-2 登录验证码可绕过（安全必问）

- [ ] **位置**：`UserServiceImpl.login`（约 92 行 `if (hasText(key) && hasText(code))`）
- [ ] **问题**：验证码仅在同时传了 key+code 才校验，不传即绕过图形验证码。
- [ ] **方案**：改为必填强校验（key/code 任一为空即抛「验证码不能为空」），并同步确认前端登录页已带验证码（`SignIn.vue` 图形验证码组件需确认存在）。
- [ ] **验证**：不带验证码调 `/api/user/login` 返回 4xx；正常携带验证码可登录。

### A2. F4 错误提示双重弹出

- [ ] **位置**：`src/views/shop/checkout/index.vue:322`、`product/detail.vue:407/418/485`、`SignIn.vue:234`、`CouponCenter.vue:250/321`
- [ ] **问题**：拦截器已 `ElMessage.error`，页面 catch 又弹一次。
- [ ] **方案**（二选一）：① 约定业务错误由拦截器统一提示、页面 catch 只处理逻辑；② `request.ts` 支持 `{ silent: true }` 配置跳过全局提示。
- [ ] **验证**：制造一次业务失败（如余额不足），只弹一次提示。

### A3. P5 权限体系自相矛盾

- [ ] **位置**：`src/utils/auth.ts:39-41`（`hasPerm()` 硬编码 `return true`）、`src/directives/permission.ts`（读恒空 `perms: []`）
- [ ] **问题**：一个全放行、一个全拦截，按钮级权限逻辑实际失效且互相矛盾。
- [ ] **方案**：统一为 store 内动态权限（登录后拉取用户权限列表写入 store，`hasPerm` 读取之）。
- [ ] **验证**：普通用户/管理员登录后，按钮级 `v-perm` 按权限正确显隐。

### A5. Q8 错误码体系落地

- [ ] **位置**：`common/Result.java`、`exception/ErrorCode.java`（已定义未用）、`exception/GlobalExceptionHandler.java`、各 Controller 的 `return Result.error("...")`
- [ ] **问题**：`Result.error` 固定 code=500，未区分 4xx/5xx，错误码体系未落地。
- [ ] **方案**：① `Result` 增加带 HTTP 状态/业务码的 error 重载；② 业务参数错误返回 400，未授权 401，越权 403，不存在 404，服务器错误 500（`AccessDeniedException→403` 已先行完成）；③ `ErrorCode` 枚举收敛业务码。
- [ ] **验证**：分别触发参数错误/未登录/越权/接口不存在，检查 HTTP 状态码与 code。

## B 组：中危（质量与性能）

### B1. Q1 Controller 手动提取 token 重复 40+ 处

- [ ] **方案**：引入 `@AuthenticationPrincipal`（登录时已存 SecurityContext）或自定义 `@CurrentUserId` ArgumentResolver，删除重复提取代码。
- [ ] **验证**：编译通过 + 抽 2~3 个接口回归。

### B2. Q9 剩余 N+1（订单/通知维度）

### B3. Q3 SKU 库存/销量汇总同步复制 4 份

### B5. Q10 吞异常 / 假实现
