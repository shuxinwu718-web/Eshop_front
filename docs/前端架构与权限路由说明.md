# E-Shop 前端架构与权限路由说明

> 本文面向开发者，梳理前端项目的整体架构、路由体系、权限检查机制，以及用户关键操作（登录、访问页面、发起请求、登出）的完整执行链路。

---

## 1. 项目概览

| 项 | 说明 |
|---|---|
| 框架 | Vue 3（Composition API + `<script setup>`） |
| 语言 | TypeScript |
| 构建 | Vite（开发端口 3000，见 `.env.development` 的 `VITE_APP_PORT`） |
| UI 库 | Element Plus（支持深色模式 `html.dark`）、VxeTable |
| 状态管理 | Pinia（setup store 风格） |
| 路由 | Vue Router 4，`createWebHashHistory`（hash 模式） |
| HTTP | Axios（统一封装于 `src/utils/request.ts`） |
| 其他 | UnoCSS、vue-i18n、wangEditor 富文本、SSE（AI 客服/消息推送） |
| 基座模板 | vue3-element-admin（保留其管理端布局/标签页能力，电商端为其上扩展） |

### 三类用户，三套布局

| 角色 | 落地页 | 布局 |
|---|---|---|
| `ADMIN` 管理员 | `/dashboard` | `Layout`（经典管理后台：侧边菜单 + 标签页） |
| `MERCHANT` 商家 | `/merchant/products` | `MerchantLayout`（商家工作台） |
| `USER` 普通用户 / 游客 | `/home` | `ShopLayout`（电商前台：顶部导航 + 移动端底部 Tab） |

## 3. 应用启动流程（main.ts）

`src/main.ts` 的装配顺序：

```
createApp(App)
 1. setupDirective(app)      # 注册自定义指令（含权限指令）
 2. setupRouter(app)         # 安装路由（静态路由即刻生效）
 3. setupStore(app)          # 安装 Pinia
 4. setupI18n(app)           # 国际化
 5. 注册 Element Plus 全部图标为全局组件
 6. configureVxeTable() + VXETable + CodeMirror
 7. setupPermissionGuard()   # 注册全局路由守卫（必须在 store 之后，因为守卫内要用 useUserStore）
 8. app.mount("#app")
```

> 注意：路由守卫在 `mount` 之前注册，因此**首次进入页面的第一次导航就会经过权限检查**。

## 4. 路由体系

### 4.1 全部为静态路由

本项目**不使用后端动态路由**。`src/store/modules/permission.ts` 中 `generateRoutes()` 直接返回空数组，`isRouteGenerated` 恒为 `true`——所有路由都定义在 `src/router/index.ts` 的 `constantRoutes` 中，可见性/可访问性完全由路由 `meta` + 守卫控制。

### 4.2 路由分组结构（index.ts）

```
/                        Layout（管理端壳）
├── /dashboard           仪表盘            roles:[ADMIN]      keepAlive
├── /operation-log       操作日志          roles:[ADMIN]
├── /management/**       管理中心          roles:[ADMIN]
│   ├── 商品管理：product / category / comment / introAudit / refund-audit
│   ├── 订单管理 / 营销管理：coupon / seckill / marketing / festival
│   ├── 用户管理：user / merchant-apply / online-user
│   └── 系统管理：notice
├── /  (Shop 分组)       ShopLayout（商城壳）
│   ├── /home            商城首页          public             keepAlive
│   ├── /seckill         限时秒杀          public             keepAlive
│   ├── /coupon-center   领券中心          public             keepAlive
│   ├── /marketing       活动中心          public             keepAlive
│   ├── /product/:id     商品详情          public
│   ├── /shop/cart       购物车            需登录
│   ├── /checkout        确认订单          需登录
│   ├── /favorites       我的收藏          USER/MERCHANT/ADMIN
│   ├── /member/center   个人中心          需登录
│   └── ...（订单/地址/签到/客服/商家小店等）
├── /merchant/**         MerchantLayout（商家端）
│   ├── /merchant/products  我的小店
│   ├── /merchant/orders    订单管理
│   └── ...（统计/退款/拼团/小店设计等）
├── /login               登录页（白名单）
└── /401 /404            错误页
```

### 4.3 路由 meta 约定

| 字段 | 作用 |
|---|---|
| `title` | 页面标题（守卫中写入 `document.title`），TagsView 与最近访问也用它 |
| `roles: string[]` | 允许访问的角色列表（`USER` / `MERCHANT` / `ADMIN`）。**不写 = 登录即可访问** |
| `public: true` | 游客可访问（无需登录），如商城首页/秒杀/商品详情 |
| `keepAlive: true` | 页面参与 keep-alive 缓存 |
| `hidden: true` | 不出现在菜单/Tab 栏 |
| `affix: true` | 固定标签（如仪表盘） |
| `icon` | 菜单/Tab 图标 |

### 4.4 keep-alive 机制（商城端）

- **管理端**：`layouts/index.vue` 内 `<keep-alive :include="cachedViews">`，`cachedViews` 来自 `tagsViewStore`，由 TagsView 组件在切换标签时注册。
- **商城端**：`ShopLayout.vue` 中 router-view 与 keep-alive **固定在布局里**（不随桌面/移动布局切换重建），并在 `watch(route.name)` 中自行把带 `keepAlive: true` 的路由注册进 `tagsViewStore.cachedViews`。
- **缓存命中条件**：路由 `meta.keepAlive === true` 且**组件名（`defineOptions({ name })`）与路由 `name` 完全一致**。例如秒杀页 `name: "Seckill"`、活动中心 `name: "MarketingCenter"`。
- **被缓存组件的注意事项**：
  - 再次进入不触发 `onMounted`，需要刷新数据的页面在 `onActivated` 中处理（首次激活跳过，避免与 onMounted 重复请求）；
  - `onUnmounted` 在切走时不会触发，定时器类资源必须在 `onDeactivated` 中停止（秒杀页倒计时/轮询即如此处理）。
- **滚动位置恢复**：
  1. 页面在 `onBeforeRouteLeave` 时（此时 route 仍是本页）把 `window.scrollY` 存入 `sessionStorage`（key：`shop_scroll:${路由name}`）；
  2. 路由实例的 `scrollBehavior` 在目标页为 keepAlive 页且路由名变化时，读取并**消费即删**该 key，返回 `{ left: 0, top: saved }`；
  3. 效果：Tab 间切换回来恢复原位置，刷新页面后从顶部开始。

## 5. 权限体系

### 5.1 角色

后端只返回单一角色（`data.role`），前端将其包装为 `roles: [role]`。三种角色：

- `ADMIN`：拥有全部按钮级权限（`perms = ["*:*:*"]` 通配）
- `MERCHANT` / `USER`：无按钮级权限（`perms = []`），只有路由级控制

### 5.2 权限检查的三个层次

| 层次 | 位置 | 机制 |
|---|---|---|
| 路由级 | `router/guards/permission.ts` | `beforeEach` 中比对 `to.meta.roles` 与当前角色，不匹配重定向 `/home`（USER/MERCHANT）或 `/401` |
| 按钮级 | `utils/auth.ts → hasPerm()` + `directives` 的 `v-hasPerm` | 比对 `userInfo.perms`，ADMIN 通配放行 |
| 接口级 | 后端 | 前端 401/403 拦截兜底（见 6.4） |

### 5.3 路由守卫完整逻辑（`setupPermissionGuard`）

```
beforeEach(to, from):
│
├─ NProgress.start()；按 meta.title 设置 document.title
│
├─ ① 未登录（无 token）
│   ├─ 重置「用户信息已加载」标志
│   ├─ to.path === "/"            → 重定向 /home（游客进商城）
│   ├─ to.meta.public 或白名单    → 放行（游客可浏览商城公开页）
│   └─ 其他（需登录页）           → ElMessageBox 弹窗「请先登录」
│       ├─ 确认 → /login?redirect=原fullPath（登录成功后回跳）
│       └─ 取消 → return false 留在当前页（游客继续浏览），手动 NProgress.done()
│
├─ ② 已登录访问 /login → 重定向 /
│
├─ ③ 确保『用户信息只请求一次』（模块级 _profileLoaded / _profilePromise 去重）
│   ├─ 未加载 → await userStore.getUserInfo()
│   │   ├─ 成功 → 标记已加载
│   │   └─ 失败 → resetAllState() → /login?redirect=...
│
├─ ④ currentRole = userInfo.roles[0]（默认 USER）
│   ├─ to.path === "/" 的角色化重定向：
│   │     ADMIN → /dashboard；MERCHANT → /merchant/products；其余 → /home
│
├─ ⑤ 角色比对：to.matched 链上任一 record 声明了 meta.roles
│   └─ 不含 currentRole → USER/MERCHANT 回 /home；否则 /401
│
├─ ⑥ 404 兜底：to.matched.length === 0 → /404
│
└─ ⑦ 全部通过 → return true

afterEach:
├─ NProgress.done()
└─ 记录「最近访问」（仅管理端页面；排除 Shop 分组与 /merchant/**）
```

关键设计点：

- **用户信息单次加载**：`_profileLoaded` + `_profilePromise` 双保险，防止守卫并发触发时重复请求 profile；登录态丢失时自动复位。
- **游客体验优先**：公开页上的未登录接口调用只提示不踢人（见 6.4），受保护页面访问用弹窗确认而非硬跳转。
- **守卫使用返回值风格**（`return true / false / 路径对象`），未使用已废弃的 `next()` 回调。

### 5.4 Token 存储（`utils/auth.ts → AuthStorage`）

- **记住我勾选**：token 存 `localStorage`（持久）；
- **未勾选**：token 存 `sessionStorage`（关浏览器即失效）；
- `isLoggedIn()` = 是否能取到 token，是守卫判断登录态的唯一依据。

## 6. 用户关键操作的执行链路

### 6.1 游客访问受保护页面（如 `/checkout`）

```
浏览器输入 URL（hash 模式 → /#/checkout）
  ↓ 路由解析匹配 Checkout 路由
  ↓ beforeEach：未登录 + 非 public
  ↓ 弹出「该页面需要登录后才能访问」确认框
  ├─ 用户点「去登录」→ 跳 /login?redirect=%2Fcheckout
  └─ 用户点「取消」→ 留在当前页
```

### 6.2 登录流程（`views/login/components/Login.vue`）

```
输入账号/密码/图形验证码（captcha 接口获取，点击图片刷新）
  ↓ handleLoginSubmit：表单校验
  ↓ userStore.login()
  │     └─ AuthAPI.login() → 后端返回 token
  │        └─ AuthStorage.setTokens(token, rememberMe)   # 写入 local/session Storage
  │        └─ 清除旧的用户信息缓存（防止上次登录残留）
  ↓ userStore.getUserInfo()                               # 拉取 profile，写入 store + localStorage 缓存
  ↓ redirectAfterLogin()
  │     ├─ URL 带 redirect 且角色合法 → 回跳原页面
  │     └─ 否则按角色落地：ADMIN→/dashboard，MERCHANT→/merchant/products，USER→/home
  ↓ 后续每次路由导航：守卫发现 _profileLoaded=false → 走 ③ 单次加载逻辑（此处已加载，直接放行）
```

用户信息读取优先级（`userStore.getUserInfo`）：

1. 内存 `userInfo`（已有 userId 直接返回）；
2. `localStorage` 带 1 小时过期时间的缓存（`user_info_cache`）；
3. 真实请求 `AuthAPI.getUserInfo()`（内部有 Promise 去重防并发）。

### 6.3 已登录用户访问页面（典型时序）

```
导航到 /seckill（秒杀页）
  ↓ beforeEach：已登录 → profile 已加载 → 角色通过（public 页）→ 放行
  ↓ ShopLayout 渲染；watch(route.name) 把 Seckill 注册进 cachedViews
  ↓ keep-alive 渲染组件；scrollBehavior 尝试恢复上次滚动位置
  ↓ 组件 setup：onMounted → fetchData() + startTimers()（倒计时 1s + 库存轮询 10s）
  ↓ 切走（如去首页）：onBeforeRouteLeave 存滚动位置 → onDeactivated 停定时器（组件被缓存而非销毁）
  ↓ 切回：scrollBehavior 恢复滚动位置 → onActivated 刷新数据 + 重启定时器
```

### 6.4 API 请求流程（`utils/request.ts`）

```
业务代码：SeckillAPI.getUserSessions()
  ↓ axios 实例 baseURL = VITE_APP_BASE_API（开发 /dev-api，生产 /prod-api）
  ↓ 请求拦截器
  │    ├─ showLoading()（全屏 loading 引用计数，防并发泄漏）
  │    └─ 自动附加 Authorization: Bearer <token>（如有）
  ↓ Vite 代理 / 后端网关
  ↓ 响应拦截器
  │    ├─ blob/arraybuffer → 直接返回（先 hideLoading）
  │    ├─ code === 200     → 解包返回 data（调用方直接拿到业务数据）
  │    ├─ 其他业务码        → ElMessage.error(msg) + reject
  │    └─ HTTP 错误：
  │         ├─ 无 response            → 「网络连接失败」
  │         ├─ 401/403 且当前页 public → 仅 ElMessage.warning 提示「请先登录」，
  │         │                            不强制跳转（保护游客浏览体验）
  │         ├─ 401/403 其他页面        → redirectToLogin()：通知 + resetAllState()
  │         │                            + 跳 /login?redirect=当前页
  │         └─ 其他状态码              → ElMessage.error(msg) + reject
  └─ finally：hideLoading()（引用计数归零才真正关闭）
```

### 6.5 游客在公开页触发需登录操作（如点收藏/抢购）

页面代码先调用 `userStore.isLoggedIn()` 判断，未登录则调用 `promptLogin()`（`utils/requireLogin.ts`）弹出引导框 → 确认后带 redirect 跳登录页。这是「公开页不硬跳转」策略的页面级配合。

### 6.6 登出流程

```
触发 logout（顶栏/移动端菜单）
  ↓ userStore.logout() → resetAllState()
  │    ├─ resetUserState：清 token（local+session）、清 userInfo、清缓存
  │    ├─ permissionStore.resetRouter()      # 静态路由模式，无需真实清理
  │    ├─ dictStore.clearDictCache()
  │    ├─ tagsViewStore.delAllViews()        # 清空标签页与 keep-alive 缓存列表
  │    └─ cleanupSseServices()               # 断开 AI 客服/通知 SSE 长连接
  ↓ router.push("/login")
```

## 7. 状态管理（Pinia）

| Store | 职责 |
|---|---|
| `user` | 登录态、用户信息（多层缓存 + 防并发）、登出重置 |
| `permission` | 静态路由模式：仅维护菜单数据与混合布局侧边菜单 |
| `tagsView` | 标签页列表 `visitedViews` + **keep-alive 缓存名单 `cachedViews`**（以路由 `name` 为缓存标识） |
| `cart` | 购物车数量（登录后拉取，登出清零） |
| `dict` | 字典缓存（登出清除） |
| `app` / `settings` | 布局偏好（深色模式、语言等） |
| `tenant` | 租户信息 |

> ShopLayout 依赖 `tagsViewStore.cachedViews` 复用管理端的缓存机制——商城模式下 TagsView 不渲染，因此由 ShopLayout 自行 watch 路由来注册缓存。

## 8. 响应式布局与主题

- **设备判定**：`composables/useIsMobile.ts` 监听窗口宽度（<768px 视为移动端）。
- **商城端**：`ShopLayout` 据此切换 `DesktopHeader` / `MobileHeader + MobileTabBar`；**keep-alive 容器固定在布局层，设备切换不会销毁缓存页面**。
- **移动端注意**：底部 Tab 栏固定定位，内容区 `padding-bottom: calc(66px + env(safe-area-inset-bottom))` 预留空间。
- **深色模式**：Element Plus 暗色变量（`html.dark`）+ 各页面自行覆盖硬编码颜色（如秒杀卡片的 `html.dark .seckill-card` 渐变覆盖）。

## 10. 常见开发约定（速查）

1. **新增商城页面**：在 `router/index.ts` Shop 分组加路由 → 组件 `defineOptions({ name })` 与路由 `name` 一致 → 需要 `meta.keepAlive`。
2. **keepAlive 页面**：数据刷新放 `onActivated`（跳过首次）；定时器在 `onDeactivated` 停止；滚动位置交给 `onBeforeRouteLeave` + 全局 `scrollBehavior`（无需页面处理保存以外的事）。
3. **权限控制**：路由看 `meta.roles`，按钮用 `v-hasPerm`；ADMIN 天然全通过。
4. **接口层**：新增模块放 `src/api/<域>/`，直接返回解包后的业务数据（拦截器已处理 code/msg）。
5. **路由守卫**：使用返回值风格（`return true/false/位置对象`），不要用 `next()`。
