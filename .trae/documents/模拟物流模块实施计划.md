# 模拟物流模块实施计划

## Context

项目已有订单→发货→签收的基础闭环（`OrderShipment` 实体、商家发货 `shipShipment`、用户确认收货 CAS 幂等、RabbitMQ 延迟插件基建），但**缺失物流轨迹**。用户将该全栈项目作为找实习的项目经历，需补齐订单全生命周期。本次以「模拟物流」方式补齐：商家发货后自动生成模拟轨迹（已揽收→运输中→派送中→已签收），用户可查看轨迹时间线；并用现有 RabbitMQ 延迟消息推进轨迹 + 实现发货后自动确认收货（简历讲点：复用延迟插件、手动 ack 幂等）。

不接入真实物流 API（避免注册外部账号依赖），模拟快递公司 + 自动生成运单号。

## 关键现状（已核实）

- 后端仓库：`C:\Users\admin\Desktop\e-shop`（勿改旧副本）
- `OrderShipment` 实体字段：id/orderId/sellerId/deliveryStatus(0/1/2)/shippingName/shippingNo/shippingTime/receivedTime/totalAmount/createTime
- 发货：`OrderShipmentServiceImpl.shipShipment`（写快递信息 + 父订单 1→2，@Transactional）
- 确认收货：`OrderServiceImpl.confirmReceive`(整单 L606) / `confirmReceiveShipment`(按发货单 L640，CAS + 全部签收→订单3)
- RabbitMQ：`RabbitMQConfig` 已有 `DELAYED_EXCHANGE="order.delayed.exchange"`（x-delayed-message CustomExchange）+ orderTimeoutQueue/binding；消费参考 `OrderTimeoutConsumer`（MANUAL ack + basicNack requeue）；发送方式 `rabbitTemplate.send + MessageProperties.setDelay(ms)`
- Controller 前缀：用户 `/api/order`，商家 `/merchant`
- 无 enums 包 → 常量类放 `constant/` 包；无 Flyway，`src/main/resources/db/` 增量 SQL 需手动执行（docker 只挂载 `./sql`）

## 实施内容

### 1. 数据库增量脚本

新建 `src/main/resources/db/V20261002__create_shipment_track.sql`：

```sql
CREATE TABLE shipment_track (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  shipment_id BIGINT NOT NULL COMMENT '发货单ID',
  order_id BIGINT NOT NULL COMMENT '冗余订单ID，便于按订单查询',
  track_status TINYINT NOT NULL COMMENT '1已揽收 2运输中 3派送中 4已签收',
  title VARCHAR(100) NOT NULL COMMENT '节点标题',
  description VARCHAR(255) NULL COMMENT '节点详情',
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_shipment_status (shipment_id, track_status),
  KEY idx_order (order_id)
) ENGINE=InnoDB COMMENT='物流轨迹表';
```

同步把建表语句加入 `sql/eshops.sql` 末尾（便于全新部署）。

### 2. 后端新增文件（后端仓库）

- `entity/ShipmentTrack.java`、`mapper/ShipmentTrackMapper.java`（BaseMapper）
- `service/ShipmentTrackService.java` + `impl/ShipmentTrackServiceImpl.java`
- `vo/ShipmentTrackVO.java`（shipmentId/orderId/shippingName/shippingNo/deliveryStatus + tracks 列表）
- `constant/TrackStatus.java`、`constant/SimulatedExpressCompany.java`（顺丰/圆通/中通/韵达/邮政）
- `mq/LogisticsTrackMessage.java`、`mq/LogisticsTrackConsumer.java`
- `OrderService` 新增 `confirmReceiveInternal(Long shipmentId)`（复用现有 CAS 签收 + 全签收→订单3，跳过 userId 校验）

### 3. RabbitMQ 配置（复用现有延迟交换机）

`RabbitMQConfig` 新增 `LOGISTICS_TRACK_QUEUE` + `LOGISTICS_TRACK_ROUTING_KEY` + Queue/Binding，**绑定到现有 `DELAYED_EXCHANGE`**（不新建交换机）。

### 4. 轨迹生成与推进（核心）

- **发货时**（`shipShipment` 事务内）：插入 track_status=1 首条轨迹 + 发延迟消息（nextStatus=2）
- **消费时**：前置校验 `deliveryStatus==1 && order.status==2 && 无该 nextStatus 轨迹`；INSERT（唯一键幂等兜底）；nextStatus<4 续发下一条延迟消息；nextStatus=4 时插轨迹 + `confirmReceiveInternal(shipmentId)`（自动确认收货）
- 异常/重复：复制 `OrderTimeoutConsumer` MANUAL ack + basicNack requeue；消费侧状态校验 + `uk_shipment_status` 唯一键天然幂等
- 延迟时长：`application.yml` 自定义块，演示用分钟级（如 pickup 1 / transit 1 / delivering 1），可配
- 兜底（消息全丢恢复）：`ApplicationRunner` 启动时扫描 `deliveryStatus==1` 且轨迹缺失的发货单，按 shippingTime 推算补发消息

### 5. 接口（并入现有 `OrderController`）

- `GET /api/order/track/shipment/{shipmentId}`：订单归属校验（shipment→order.userId==当前用户）
- `GET /api/order/track/order/{orderId}`：返回该订单全部发货单轨迹组
- 未发货/无轨迹返回空 tracks（前端空态）

### 6. 前端（前端仓库）

- 路由：ShopLayout children 加 `/order/track/:shipmentId`，name `OrderTrack`，组件 `views/shop/order/track.vue`，meta `{ title:"物流跟踪", hidden:true, hideMobileTabbar:true, roles:["USER","MERCHANT","ADMIN"] }`
- 页面：顶部快递公司/单号/状态 tag + `el-timeline` 正序轨迹（status 映射图标色），`formatDateTime` 时间；空态 `el-empty`
- API：`src/api/eshop/order.ts` 新增 `ShipmentTrackVO` 类型 + `getShipmentTrack(shipmentId)` / `getOrderTrack(orderId)`
- 入口：`views/shop/order/detail.vue` 物流步骤条区加「查看物流」按钮 → `router.push('/order/track/'+shipmentId)`；列表页已发货卡片可选加
- 商家端小改：`views/merchant/Orders.vue` 发货弹窗 shippingName 改 el-select（模拟快递公司文案），shippingNo 自动生成随机单号回填（后端零改动）

## 验证方式

1. 本地执行增量 SQL → `SHOW CREATE TABLE shipment_track`
2. 后端 `mvn -q compile` 通过
3. 启动后端，RabbitMQ 管理台确认 `logistics.track.queue` 自动声明
4. 走单验证：下单→支付→商家发货（选快递公司，自动单号）→观察日志 4 条轨迹逐级推进（分钟级延迟）→自动确认收货→订单变已完成
5. `curl /api/order/track/shipment/{id}` 验证轨迹列表与归属校验；未发货单返回空 tracks
6. 前端 `pnpm build` 通过；浏览器：订单详情「查看物流」→ 时间线展示；移动端底部操作栏不遮挡
7. 回归：手动确认收货流程不受影响（已签收发货单重复点击提示幂等）
