# Eshop 电商系统 —— 需求规格说明

> **毕业设计课题**：基于 SpringBoot + Vue3 的 B2B2C 电商购物系统  
> **开发者**：个人开发  
> **开发周期**：约 2 个月（非全天投入）  
> **文档版本**：v2.0  
> **更新日期**：2026-07-23

---

## 一、项目概述

### 1.1 项目定位

面向 C 端消费者的电商购物系统，支持商品浏览/搜索、购物车、下单支付、订单管理、优惠券、签到奖励等完整购物闭环。系统包含三种角色：普通用户（USER）、商家（MERCHANT）、平台管理员（ADMIN）。

### 1.2 技术约束

| 约束项 | 说明 |
|--------|------|
| 支付实现 | 模拟支付，不接入真实支付渠道（支付宝/微信） |
| 物流对接 | 模拟物流轨迹，不接入快递100/菜鸟等真实API |
| 开发时间 | 约2个月，非全天投入（预估有效工时约 200-250h） |
| 部署方式 | Docker Compose 本地部署（MySQL + Redis + ES） |

### 1.3 技术栈

| 层级 | 技术 |
|------|------|
| 前端框架 | Vue 3 + TypeScript + Vite |
| UI 组件库 | Element Plus |
| 状态管理 | Pinia |
| 路由 | Vue Router |
| HTTP 客户端 | Axios |
| 样式方案 | SCSS + UnoCSS |
| 后端框架 | Spring Boot 3.2.2 |
| ORM | MyBatis-Plus 3.5.6 |
| 数据库 | MySQL 8.0 |
| 缓存 | Redis 7 |
| 搜索引擎 | Elasticsearch 8.11.0 |
| 安全认证 | Spring Security + JWT |

**订单状态机**：

```
待付款(0) ──支付──→ 已付款(1) ──发货──→ 已发货(2) ──确认收货──→ 已完成(3)
   │                   │                    │                    │
   └──取消──→ 已取消(4)  └──申请退款──→ 退款中(5) ←──申请退款──┘
                                           │
                                    审核通过/拒绝
                                           │
                                    通过→ 已退款(6)
```

## 六、创新点说明

### 6.1 节日优惠券 + 签到联动机制

打破传统「签到领固定奖励」模式，引入**节日驱动的动态奖励体系**：
- 每个节日活动独立配置签到门槛（如618只需3天、双11需要7天）
- 用户签到进度对每个活动独立计算，可视化展示
- 活动与优惠券模板解耦（通过 `festival_coupon_plan` 关联），灵活配置

### 6.2 签到里程碑可视化

将传统的「连续签到X天」数字提示升级为**4节点进度条**：
- 3天 → 7天 → 14天 → 30天，每个节点标注具体奖励内容
- 状态三态：🔒 未解锁 → 🎫 已达成 → ✓ 已领取
- 进度条 + 文案提示「再签到X天即可获得新奖励」

### 6.3 退款全生命周期闭环

从简单「申请→审核」升级为完整售后链路：
- 退款原因结构化分类
- 多级审批（商户→管理员）
- 进度节点记录（申请时间→商户审核→管理员审核→退款执行→完成）
- 满意度反馈（退款完成后收集用户评价）

## 七、功能边界（不做）

以下功能经评估后**明确不纳入**本次毕业设计范围：

| 功能 | 排除原因 |
|------|----------|
| 拼团购 | 并发超团风险高、测试复杂、时间不足 |
| 商品视频展示 | 用户决定不实施 |
| 直播带货 | 需第三方SDK、开发周期长 |
| 真实支付对接 | 个人开发者无法接入支付宝/微信商户 |
| 真实物流对接 | 快递100/菜鸟API需企业资质 |
| 3D商品展示 | 前期投入大、与核心业务关联弱 |
| 社区种草/晒单 | 内容审核复杂度高 |
